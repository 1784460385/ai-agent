前端是单页应用，所有页面共享一个 AuthProvider 和 http 拦截器（带 JWT）。
后端是一个 FastAPI 实例，按功能拆成多个 router：auth、admin、keys、history、threads、以及 main.py 里的 /api/chat、/api/upload、/api/index、/api/folders、/api/documents。
所有数据按用户隔离：文件夹、文档、向量集合、API Key、对话历史都带 user_id。
二、AI 相关的三条主线
整个系统的「智能」来自三个独立但协作的模块：embedding 检索、对话路由与改写、大模型生成。

1. 知识库的向量化与检索（本地 AI）
这一层完全在服务器本地跑，不调外部 API。

模型：BAAI/bge-m3，一个多语言 sentence-transformers 模型，约 2GB。

下载：model_download.ensure_local_model 在首次需要时把模型从 HuggingFace 拉到 backend/models/，支持断点续传和镜像（HF_ENDPOINT）。下载完成后不再联网。

向量化：ChromaDB 的 SentenceTransformerEmbeddingFunction 包住这个本地模型，把每段文本转成向量，存进 backend/chroma_db/。

检索：vector_store.search_departments 对每个选中的文件夹集合做 collection.query，按余弦距离取 top 3。返回的是片段原文 + 来源 metadata。

这一层的意义：让模型「知道」用户的私有资料，而不是只靠训练时的通用知识。

2. 对话路由与检索 query 改写（调用外部小模型）
这一层调 DeepSeek，但用的是轻量调用，目的是让检索更准。

路由（router.route_query）：

先跑规则：每个文件夹配了关键词，正则命中就只查这几个文件夹。
没命中再调 LLM：把所有文件夹的名称和描述喂给 DeepSeek，让它返回 JSON 格式的 key 列表。失败时回退到全部文件夹。
query 改写（这次改造新加的，context_memory._rewrite_query）：

用户说「它怎么配置」时，单看这句话没法检索。
用历史摘要 + 最近一轮用户问题 + 当前问题，让 DeepSeek 改写成一条能独立检索的 query（如「Nginx 反向代理 HTTPS 配置」）。
改写后的 query 同时用于路由判断和向量检索。
上下文摘要（context_memory._summarize）：

保留最近 2 轮原文，更早的轮次在达到 token 阈值时做增量摘要。
摘要也调 DeepSeek，但只生成 800 token 以内的要点，成本很低。
同一会话有锁，避免并发重复摘要。
这一层的意义：让检索又准又省——路由避免扫全部文件夹，改写解决指代问题，摘要控制上下文长度。

3. 大模型生成（外部主模型）
这是用户最终看到的回答来源。

拼 prompt（rag_engine.build_rag_prompt）：

system prompt 里写死规则：有依据就按原文答并标来源；没有就自己答，但第一句必须说「知识库中没有可引用的内容」。
检索到的片段用 [来源: xxx]\n内容 格式拼进 system。
历史摘要、未摘要旧原文、最近两轮原文、当前问题依次拼进 messages。
流式生成：

用 AsyncOpenAI 调 DeepSeek 的 chat.completions.create(stream=True)。
后端把模型输出包成 SSE 事件（sources、router、delta、done、error）发给前端。
前端 useChat 边收边渲染，支持中途 AbortController 停止。
生成完成后把问题、回答、引用、命中的文件夹存进 chat_history，供下次上下文用。
附件处理（chat_attachments）：

用户可以在提问时附带文件或图片。
文档类被解析成文本拼进 user message；图片类转 base64 data URL，只有 vision 模型（deepseek-flash 等）能处理。
附件不进知识库，只影响这一次提问。
这一层的意义：把检索到的私有知识和模型的通用能力结合，回答既要有依据，又能在没有依据时兜底。

三、一次提问的完整 AI 链路

用户输入「它怎么配置 HTTPS？」
  │
  ├─ 1. 读取会话历史：摘要 + 最近2轮原文
  ├─ 2. 改写检索 query → 「Nginx 反向代理 HTTPS 配置」
  ├─ 3. 路由：规则没命中 → LLM 判断 → 选中「技术部」文件夹
  ├─ 4. 在「技术部」向量集合里 query，取 top 3 片段
  ├─ 5. 拼 system prompt：RAG 规则 + 3 条片段
  ├─ 6. 拼 messages：system + 摘要 + 最近原文 + 当前问题
  ├─ 7. 调 DeepSeek 流式生成
  ├─ 8. 前端逐字显示，下方展示引用来源
  └─ 9. 存对话历史，更新摘要指针
四、几个关键设计点
用户隔离：向量集合名带 user_id，API Key 加密后绑定 user_id，对话和文档都按用户过滤。一个用户的知识库不会被另一个用户检索到。

本地 + 外部混合：embedding 在本地（省 API 费、数据不外泄），生成调外部模型（借大模型能力）。路由和改写也调外部，但调用很轻。

流式而非一次性：从后端到前端全程 SSE，用户不用等模型写完才看到字，体验上接近 ChatGPT。

检索有上限：路由选文件夹 + 每文件夹 top 3 + 每块 500 字，三层收口，知识库再大也不会把 prompt 撑爆。

上下文有记忆：摘要 + 最近原文，长对话不会因为窗口限制而失忆，也不会因为全量历史而爆 token。

失败可降级：路由 LLM 挂了回退全部文件夹，摘要失败就临时带旧原文，改写失败就用原话检索——每个 AI 调用都有兜底，不会因为一个环节挂了就整个提问失败。
