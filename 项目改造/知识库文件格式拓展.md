1. 任务背景与目标
当前状态：系统仅支持 PDF、Markdown、TXT 三类纯文本/半结构化文件。
扩展目标：根据业务需求，分阶段支持办公文档、表格、网页及非结构化数据，同时保证解析质量、处理性能和系统安全性。

2. 格式扩展优先级规划
🟢 第一优先级：必须补充（办公必备）
这是企业知识库最常见的来源，建议立刻支持：

格式	扩展名	典型场景	解析难点
Word	.docx, .doc	制度文件、合同、报告	图文混排、页眉页脚噪声
Excel	.xlsx, .xls	数据表、预算表、清单	表格结构丢失（转为纯文本后失去行列关系）
PowerPoint	.pptx	培训材料、演示文稿	幻灯片顺序、备注页提取
AI 实现指令：

在 config.py 中新增 SUPPORTED_EXTENSIONS 配置，将上述扩展名纳入白名单。

修改 rag_engine.py 的 load_and_split_documents()，引入 LangChain 对应的 Loader：

Word：from langchain_community.document_loaders import Docx2txtLoader

Excel：from langchain_community.document_loaders import UnstructuredExcelLoader（需安装 unstructured、openpyxl）

PPT：from langchain_community.document_loaders import UnstructuredPowerPointLoader

补充 Python 依赖至 requirements.txt：

text
python-docx
openpyxl
unstructured
markitdown[all]  # 推荐，可统一处理 Office 文档
🟡 第二优先级：按需补充（技术与数据部门）
如果知识库面向技术团队或数据分析场景，建议补充：

格式	扩展名	典型场景	解析方案
HTML	.html, .htm	网页存档、内部 Wiki	UnstructuredHTMLLoader
CSV	.csv	数据导出、日志	pandas.read_csv 后转为 Markdown 表格
JSON	.json	API 文档、配置说明	json.load 后递归展平为文本
Jupyter Notebook	.ipynb	技术教程、数据分析	langchain_community.document_loaders 中的 NotebookLoader
AI 实现指令：

表格类（Excel/CSV）：不要直接转纯文本，建议转为 Markdown 表格 或 HTML 表格 存入向量库，这样大模型能理解行列关系。

python
import pandas as pd
df = pd.read_csv(file_path)
markdown_table = df.to_markdown(index=False)
HTML：使用 BeautifulSoup 提取正文，剥离 <script> 和 <style> 标签，避免噪声进入向量库。

🔵 第三优先级：进阶补充（非结构化数据）
如果业务涉及扫描件、图片或音视频，需要引入更复杂的处理链路：

格式	扩展名	处理方案	成本与复杂度
图片	.jpg, .png	使用 PaddleOCR 或 Tesseract 提取文字	高（需 OCR 模型）
扫描版 PDF	.pdf	使用 pdf2image + OCR 或 PyMuPDF 提取	高
AI 实现指令：

此类格式建议异步处理，上传后进入队列（如 Celery 或 FastAPI BackgroundTasks），前端显示“解析中”状态，避免阻塞请求。

若短期无相关需求，可在前端暂时禁用这些格式，或显示“即将支持”提示。

3. 前端 UI 改造建议
根据扩展结果，前端需要同步调整：

上传区提示文案：从“PDF / Markdown / TXT”改为动态渲染，从后端 /api/config 接口获取支持的格式列表。

tsx
<p className="text-sm text-slate-400">
  支持 {supportedFormats.join(' / ')}，单个不超过 {maxSizeMB}MB
</p>
文件图标区分：根据扩展名显示不同图标（Word 用蓝色、Excel 用绿色、PPT 用橙色），提升辨识度。

解析状态反馈：

上传后显示进度条或状态标签：排队中 → 解析中 → 索引完成 / 解析失败。

对于 OCR / 音频类文件，明确提示“该格式解析较慢，预计需要 X 分钟”。

失败重试：对于解析失败的文件，在列表中提供“重试”按钮，并显示失败原因（如“PDF 加密无法解析”）。

4. 工程化注意事项
安全性：

白名单校验：在后端严格校验扩展名和 MIME 类型，禁止 .exe、.zip、.js 等可执行或脚本文件上传。

大小限制：建议对 Office 文档限制在 50MB，图片限制在 20MB，音视频限制在 200MB（需单独配置）。

病毒扫描：如果是对外服务，建议接入 ClamAV 等工具扫描上传文件。

解析性能：

Office 文档解析较慢，建议设置超时（如 60 秒），超时后标记为失败。

大文件（如 100 页 PDF）应分片处理，避免内存溢出。

解析质量：

Excel 表格：如果表格跨越多页或包含合并单元格，纯文本提取会丢失结构，建议转为 Markdown 表格或直接存储为结构化 JSON。

Word 文档：需剥离页眉、页脚、批注等噪声，只保留正文和标题层级。

PPT：按幻灯片顺序提取，同时保留演讲者备注。

依赖管理：

unstructured 库依赖较多（如 libmagic、poppler），在 Docker 部署时需安装系统依赖，建议在 Dockerfile 中提前配置。

推荐使用 markitdown（微软开源）作为统一入口，它可以将 PDF、Word、Excel、PPT、HTML、图片等统一转为 Markdown，极大简化解析流程。

AI 完成扩展后，按以下标准验证：

检查项	预期结果
